# BC 사이클 6-가 결과 — 붉은실 예고 예측기 **작동** (2026-09-09)

## 설계
- Positive: 피격 순간 -1.32초(예고 노출 구간, -40~-10프레임) = 85 샘플
- Negative: 보스전 나머지 = 4,363 샘플 (총 4,448)
- 관측: 붉은 픽셀 7레인 분포 + 최대값 (8 특징)
- 모델: RandomForest 200트리, class_weight=balanced

## 결과 — **예고 감지 성공**

| 지표 | 값 |
|---|---|
| **macro-F1 (5-fold)** | **0.886 ± 0.039** |
| negative precision/recall | 0.991 / 1.000 |
| **positive(예고) precision** | **1.000** |
| positive recall | 0.529 |
| 정확도 | 0.991 |

**해석**:
- positive precision 1.000 = 예측기가 "예고 있다"고 말하면 **100% 맞다** (거짓 경보 0)
- positive recall 0.529 = 실제 예고의 53%만 잡아냄 — **놓치는 예고가 있음**
  (라벨 노이즈: "예고가 보였지만 회피 성공"한 프레임이 negative로 오분류)
- top features: lane1, lane0, lane2, max — 레인 위치 정보가 실제로 신호

## 이것이 의미하는 것
**관측 병목(위협 공간 위치)의 해결책이 실증됐다.**
- 사이클 1~5에서 "관측에 위협 위치가 없어서 ML이 안 된다"는 걸 측정으로 확정했고,
- 사이클 6-가에서 그 위치 정보로 **예고를 맞히는 예측기(precision 1.0)**를 만들었다.
- 이 예측기를 관측 브리지에 연결하면 "1.32초 후 어느 레인에 실이 나오는가"가
  에이전트의 관측에 들어온다 → BC/RL의 관측 문제가 풀리는 경로.

## 남은 개선
1. recall 0.529 → 라벨 노이즈 감소(회피 성공 구간의 정확한 라벨링) + 데이터 추가
2. 예고 "위치"(레인) 예측으로 확장 (현재는 존재 여부만)
3. 관측 브리지 연결 → BC 사이클 7 (예고 정보로 전문가 행동 재예측)
