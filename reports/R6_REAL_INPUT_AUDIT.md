# R6 실입력 감사 보고서 (2026-09-08) — 납품 철회 및 근본 원인 특정

## 결론
이전 '실입력 작동 증명 영상'은 **허위 판정**이었음. 납품 철회.
- MOVED:YES 판정 로직의 결함: idle diff에 게임 배경 파티클 애니메이션 기저 노이즈가
  반영되지 않음 → 이펙트 변화를 '이동'으로 오판
- 정밀 감사(템플릿 매칭 conf 0.94): 발화 전후 캐릭터 위치 변화 = **0px**

## 근본 원인 (실험 3건으로 특정)
1. `pydirectinput` (SendInput, VK 방식): 키 발화 후 **GetAsyncKeyState = 0x0**
   — 내 프로세스에서조차 입력 스트림에 안 들어옴 → 시스템 레벨 필터 존재
2. `PostMessage(WM_KEYDOWN)` 직접 전송: **액세스 거부(UIPI/게임가드)** — 게임 토큰
   elevation 2 (elevated), 내 토큰 elevation 3 (UIAccess)임에도 거부 → 게임가드 자체 필터
3. SendInput 스캔코드 방식 + 0.8초 홀드: 역시 캐릭터 0px, GetAsyncKeyState 무반응

## 구조적 의미
- 이 프로젝트 초기 실측("Hermes 프로세스에서 GetAsyncKeyState/SendInput 차단,
  pydirectinput만 게임창 도달")은 **불안정/부분적 사실**이었음. 이번 재검증에서는
  pydirectinput의 SendInput도 차단됨 — 상태가 시간/세션/게임가드 버전에 따라 변동
- 결론: **게임가드가 작동 중인 메이플 클라이언트에 대한 소프트웨어적 키 주입은
  (VM/드라이버 계열 없이는) 신뢰 불가**. 이는 에이전트가 아닌 환경의 물리적 제약.

## 품질 신뢰도 개선 (사용자 지정 목표)
1. **MOVED 판정 기준 교체**: 화면 diff 대신 **캐릭터 위치 템플릿 매칭(측정)** —
   이동 판정은 px 변화로만. 파서 플레이어 검출(yolo/HSV)과 결합
2. **증명 영상 표준**: "판정 패널 + 측정 좌표"를 세트로. 판정 근거 데이터가
   프레임에 함께 새겨지도록 개정 (허위 PASS 구조적 방지)
3. **납품 전 2단계 검증 의무화**: 판정 로직 자체를 (a)측정값 (b)독립 검증
   (템플릿 매칭/YOLO)으로 교차 확인 후 납품. 이번 사례가 프로세스 표준이 됨
